# Toward a model that searches in one shared state

Status: research design, 26 September 2026. The [compact-state pilot](COMPACT_STATE_PILOT_2026-09-26.md) built an exact decision-diagram reference and found that a separate fuzzy-inhibition 4B arm failed. No model has been trained to construct this factor state from tasks, and no gain is claimed.

## The gap

The released Interference Search system expands explicit states, merges exact duplicates, and uses a trained Countdown judge to prune them. It establishes that this search shape can help when the domain supplies moves and state equivalence. The strongest Countdown arm does not ask a language model to propose moves or maintain the frontier. The code result is one solved problem ahead of independent sampling on 30 tasks, within noise. Those results do not yet establish a new model architecture.

The next claim should be harder: **a model can maintain one compact, revisable representation of many possible solutions, use verified failures to remove whole regions, and recover a viable solution without materializing every path.** The representation must affect the model's recurrent computation and its next proposal. A controller that simply runs many model calls and deduplicates their outputs would reproduce the release architecture.

## Proposed mechanism: a revisable hypothesis register

The model carries a register `S = (V, F, B, P)` between reasoning steps. `V` holds typed decision variables and their possible values. `F` holds sparse factors and their scopes, rather than a list of complete branches. `B` holds learned messages and scores. `P` holds provenance: which prompt span, model edit, or verified observation created each factor. A full hypothesis is an assignment to `V`; the register represents a distribution over assignments without listing them all.

The language model has four operations. It **declares** variables and local relations from the task, **queries** a candidate for execution, **refines** the register after feedback, and **reads out** a solution. A recurrent state layer passes messages between variables and factors between model steps. Selected decoder layers cross-attend to this state; the next model proposal must be conditioned on the updated register. These are trainable operations, not a hand-written Countdown proposer or judge.

The distinctive operation to test is **scoped refutation**. A failed candidate by itself proves only that candidate wrong. To subtract a whole region, the model proposes a predicate on a subset of decisions and a verifier supplies or checks a certificate that every assignment matching it fails. The accepted predicate becomes a hard factor. One update then suppresses all matching assignments, including ones never proposed. If no sound certificate exists, the register stores only a full-candidate exclusion. Model guesses about broader failure regions stay soft and cannot erase the correct answer. Record the breadth and validity of every exclusion.

The other necessary operation is **adaptive refinement**. Two partial hypotheses may share a factorized state while the evidence available so far cannot distinguish them. A new counterexample can split their shared class. The model must propose a refinement of the factor scopes, and the register must retain enough provenance to reconstruct both sides of the split. If it cannot recover a valid member after the top candidate is refuted, the claimed compact state has lost information.

For an assignment `h`, the score has the form `log p(h | S) = sum_f phi_f(h_scope) - Z`. The model produces the local factor potentials; it cannot score every complete assignment through an uncounted global head. A verified exclusion assigns `-infinity` to a certified invalid region; a learned warning changes local scores but never the hard support. The signed update is useful only if the learned scopes and refinements let one piece of evidence affect the right family of hypotheses. A factor can stand for many paths only when the task has reusable structure. With `n` decisions of `q` values and `m` factors of bounded arity `k`, stored tables can be `O(nq + mq^k)` instead of `q^n` paths. Exact inference may still be exponential in graph width, and a counterexample that only excludes one complete assignment gives little compression. Track these failure cases explicitly.

This is a specific architectural bet: the language model learns to build and revise the abstraction from unstructured task evidence, while an auditable factor register carries many candidate programs through each step. The register and recurrent update layer are part of the model's forward path. The verifier only executes proposals and validates certificates. The first version keeps scopes, hard masks, and provenance explicit. A later latent version must match its behavior before claiming a more compact implementation.

## Why this is a model experiment

The model, rather than a hand-written Countdown domain, must perform the choices that matter: build the state, propose distinct candidates, decide what evidence affects, and read a solution from the revised state. The environment is limited to execution and exact feedback. A frozen verifier is allowed, but every candidate and factor proposal is charged to the model. Report model tokens, factor updates, verifier calls, peak memory, FLOPs, and end-to-end latency. A claim of native model reasoning must also show that removing or corrupting the factor pathway at evaluation time changes behavior.

The first test is not open-ended code. Start with a **source-disjoint, compositional program-induction family**: small typed programs built from held-out combinations of operators, with input-output examples and counterexamples. A program chooses an operation at each position. For each example, intermediate values become local state variables and each operation contributes a transition factor. A new input-output counterexample then constrains many programs at once through those shared transitions. The learner receives the operator descriptions and examples, but no oracle factor graph or correct program at evaluation. The verifier executes complete proposals and returns a failing case. Task generators, operator combinations, and program templates must be disjoint across train, validation, and test.

Evaluate twice: once with structured operator tables to isolate the state-update mechanism, and once with descriptions the language model must parse. Keep a known-grammar exact solver, a cached enumerator, and a deterministic factor-graph solver as serious baselines. The structured comparison gives them the same rules and evidence; the text comparison charges parsing to every system. If the deterministic baselines solve the family cheaply, the model has not earned a compute claim there.

The preflight should include cases where factorization is genuinely useful and cases where it breaks. Independent constraints should let one certified failure remove many assignments. Coupled parity or long-range constraints should force the state to retain correlations; single-variable marginals will give the wrong answer. Test counterfactual recovery by invalidating the highest-scored candidate and checking whether the correct surviving candidate can still be decoded without starting over. Also test broad but *uncertified* counterexamples: the model must not turn them into hard exclusions.

## Training path

**Local mechanistic preflight.** Implement a small factor updater and decoder in PyTorch. Train a small model from scratch on generated tasks only to check that load, forward, backward, optimizer update, changed weights, save/reload, and held-out behavior all work. Compare to exact factor updates and a deterministic cached solver. This is a mechanism check, not a claim about a capable language model. No rented GPU is needed for its first smoke.

**Capable-base pilot.** Keep a strong pretrained base model. Add the register, recurrent message layer, cross-attention, and operation heads. Begin with supervised traces produced by exact task solvers, including pairs that share a prompt and differ only in one counterexample. Train the model to reuse its prior register, apply that one update, and decode the changed answer. Also pair different wording of the same rules so the register learns their shared structure. The losses cover valid factor edits, candidate quality, hard-mask fidelity, final correctness, and recovery after a counterexample. At evaluation the model receives the raw task and verifier feedback, not oracle state labels. Train matched arms with the same base, data, parameter budget, and optimizer work: a plain scratchpad, a cached explicit frontier, a fixed factor graph, and the revisable register. Include a version with the same extra supervision but no shared state, so the gain cannot be credited to labels alone. Train the new modules and selected base layers, then test whether full-weight continued training is needed.

**Scale only after the pilot.** If the module causally helps and survives source-disjoint tests, run a measured throughput and memory smoke on the chosen 27B-class or larger base. Set a GPU-hour cap from the observed tokens per second before full training. Continue training on a mixture of ordinary language and checkable search trajectories so general ability does not collapse. Then use verifier-backed RL to reward final correctness, distinct useful proposals, recovery after refutation, and total work. The exact model and compute allocation are still undecided.

## Comparison that could defeat the idea

The primary comparison is solve rate at **matched total work** against the same base model with a long chain, best-of-N, a cached explicit search graph, and a deterministic or learned factor-graph baseline given the same parsed task. Count all model forward passes, factor updates, verifier calls, and cache work. Also report wall-clock latency, peak memory, and energy where measurable. Equal generated tokens alone are insufficient.

The mechanism checks are separate from the score:

- A verified exclusion should reduce probability mass on the certified subspace, including unvisited members, without deleting valid neighboring hypotheses. An uncertified failure should not cause hard suppression beyond its tested candidate.
- Shuffling evidence between tasks, blanking the factor state, or disabling the inhibitory update should remove the claimed gain if the model uses that path.
- A counterexample that distinguishes previously merged hypotheses should split their class, and the decoder should recover a viable alternative without rebuilding the state from the transcript.
- Performance should hold as the number of represented candidate paths grows beyond the number of factor slots. Record factor count, memory, and update cost, not just path count.
- A model with the same parameters and extra supervision but no factor state should lose under a paired, multi-seed comparison. If it ties, the architectural claim fails.

Use several seeds and confidence intervals over source-disjoint tasks. Do not call a win on a few dozen tasks a breakthrough. The stronger claim needs all three: a causal state-path effect under ablation, a clear accuracy-versus-total-work improvement over the best cached or factorized baseline on held-out structures, and transfer to a second task family with different rules. General reasoning ability requires a separate, broad evaluation after integration with the capable base. A one-H100 run can establish feasibility and a promising signal; it cannot establish all of these claims alone.

## Compute decision

Three costs must be kept separate. A small from-scratch model checks the mechanism but cannot establish a very capable assistant. An adapter or selective fine-tune of a pretrained model is the cheapest capable-base test. Full-weight continued pretraining is the expensive integration step, justified only by measured gains and a native throughput smoke. At Runpod's 13 September 2026 Secure Cloud listed rate of $3.49 per H100 SXM GPU-hour, eight GPUs for seven days cost about $4,691 in rental before storage, idle time, failed runs, and evaluation. That number is an arithmetic example, not a training estimate. No paid run is specified or authorized by this design.

## Adjacent work

The release paper already covers explicit graph search and merging. APR trains parallel spawn and join operations. Reasoning by Superposition provides a theoretical continuous-state construction, while The Illusion of Superposition reports that fine-tuned latent-thought models in its experiments usually did not use superposition. Learned belief propagation trains message updates. BLAZE already uses counterexample-guided abstraction refinement to compact program search. These make generic claims about factor graphs, refutation, or abstraction refinement inappropriate. The possible contribution here is a language model that **constructs, revises, and uses** one shared hypothesis register from unstructured task evidence and improves end-to-end reasoning at matched work. That remains a hypothesis.
